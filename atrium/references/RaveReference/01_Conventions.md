> Conventions
>
> This documentation uses the following conventions.
>
> Tags
>
> This documentation uses the following conventions for tags.
>
> |  |  |
> | --- | --- |
> | Note | Matters of specific importance. |
>
> |  |  |
> | --- | --- |
> | See also | Cross-references |
>
> |  |  |
> | --- | --- |
> | Example | An example. |
>
> |  |  |
> | --- | --- |
> |  | A drop-down hotspot link. When you click the link, a screen shot or a menu command description is displayed or hidden. |
>
> |  |  |
> | --- | --- |
> |  | Indicates that the function contains legacy information. The tag remains stationary in the upper left corner of the topic, regardless of how the page is scrolled. |
>
> Type styles
>
> This documentation uses the following conventions for type styles:
>
> |  |  |
> | --- | --- |
> | Italic | Cross-references. |
> | Bold | Names of GUI components, such as buttons, boxes, fields, menus and commands. |
> | Monospaced | Data and choices entered such as file names, values and parameters. |
> | Initial Capitals | Names of forms and services, for example Plan Manager. |
> | > | Menu choices.  For exampleHard Locks> Set means select Hard Locks from the menu and select Set from the submenu. |
>
> BNF notation
>
> This documentation uses BNF notation when describing code syntax. The following meta symbols are used:
>
> |  |  |
> | --- | --- |
> | ::= | Is defined as. |
> | | | or |
> | \* | The preceding item is repeated zero or more times. |
> | + | An item is repeated one or more times. |
> | (x1 | x2)\* | Parentheses are used to group items. |
> | [remark] | Optional items are enclosed in meta symbols (square brackets). |
>
> The following type styles are used:
>
> |  |  |
> | --- | --- |
> | variable | Distinguishes syntax rule names (also called non-terminal symbols or category names). |
> | parameter | Indicates terminal symbols (reserved words), which are to be written exactly as presented. |
